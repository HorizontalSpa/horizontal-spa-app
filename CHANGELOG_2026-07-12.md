## Почему изменения не были видны в приложении

Причин было несколько, каждая по себе ломала работу:

1. **Продовый сервер не запускал API.** `server-render.js` (именно он указан как Start Command на Render) отдавал только статику из `build/` — ни `/api`, ни подключения к базе данных там не было вообще. Любые вызовы API из фронтенда были обречены на неудачу в проде.
2. **Не был подключён Telegram WebApp SDK.** В `public/index.html` отсутствовал `<script src="https://telegram.org/js/telegram-web-app.js">`. Без него `window.Telegram.WebApp` не существует, и React-приложение не могло определить, что оно открыто в Telegram — показывало заглушку для браузера.
3. **Реальный React-фронтенд, который собирается и деплоится (`src/` в корне), был почти пустой заглушкой.** Компоненты `Benefit`, `Profile`, `Ranking`, `WebVersion` буквально возвращали `<div>Бонусы</div>` — один и тот же текст. Более полнофункциональная версия компонентов лежала в удалённой папке `@sindresorhus/is/frontend` — но она не участвовала в сборке (свой отдельный `package.json`), так что править её было бесполезно.
4. **Авторизация создавала нового случайного пользователя при каждом входе** (`Math.floor(Math.random() * 1000000)`) вместо использования настоящего Telegram ID — личный кабинет никогда не смог бы запомнить историю или бонусы конкретного человека.
5. **Бонусы и визиты нигде не начислялись.** Функции `updateBalance` и `incrementVisits` в `db.js` существовали, но их не вызывал ни один маршрут API.

## Что сделано

- Фронтенд переведён с Create React App на Vite (`vite.config.js`, `index.html` в корне, `package.json` обновлён). Старая директория `public/` с альтернативной vanilla-JS версией перемещена в `legacy-vanilla-app/`, чтобы не конфликтовать со сборкой Vite.
- `server.js` и `server-render.js` объединены: теперь один и тот же сервер (`server.js`) поднимает API, подключает БД и отдаёт собранный фронтенд; `server-render.js` просто вызывает его — настройки Render менять не нужно.
- Добавлен `telegram-web-app.js` в `index.html`.
- Переписаны компоненты фронтенда (`WelcomeCard`, `Home`, `Booking` (новый — форма записи), `Profile`, `Benefit`, `Ranking`, `Banners` (новый), `WebVersion`) — теперь реально обращаются к API, а не показывают заглушки.
- `/api/auth` переписан: парсит и (в production) проверяет подпись настоящего Telegram `initData` (HMAC по алгоритму из документации Telegram), создаёт клиента по его реальному Telegram ID.
- Добавлено начисление бонусов: за визит (после того как он отмечен завершённым), за отзыв, и дополнительный бонус за каждые 10 визитов.
- Добавлен эндпоинт `POST /api/appointments/:id/complete` — отмечает визит завершённым и триггерит начисление бонуса. **Пока без защиты — доступен всем, кто знает URL. Нужно закрыть перед реальным использованием** (см. README).
- Добавлены `GET /api/masters` и `GET /api/banners` (пока со статичными данными, легко редактируются прямо в `routes/api.js`), поле `master` в таблице `appointments` (+ миграция `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, чтобы не сломать уже существующую БД на Render).
- Исправлена выдача истории записей: раньше запрос не подтягивал оценку (`rating`), из-за чего кнопка «оставить отзыв» показывалась бы всегда, даже после того как отзыв уже оставлен.

## Известные ограничения / что дальше

- Раздел «Мастера» — статичный список из трёх имён в коде, реальной привязки к расписанию/занятости нет (это уже из вашего следующего этапа — «мониторинг свободных окон»).
- Баннеры — статичный массив в `routes/api.js`, без админки для редактирования.
- Нет интерфейса для персонала (отметить визит завершённым можно только вызовом API напрямую).
- Витрина товаров, оплата, дашборд, пуши, синхронизация с YC — не входили в этот этап, эндпоинты для товаров (`/api/products`) уже есть в API, но экрана в приложении под них ещё нет.
- Сборка (`npm run build`) не была прогнана здесь «вживую» — среда, в которой я работал, не имеет доступа к npm-реестру. Код прошёл статическую проверку (синтаксис всех бэкенд-файлов, целостность импортов и экспортов фронтенда), но реальный `npm install && npm run build` стоит один раз прогнать локально или довериться сборке на Render перед тем, как переключать бота на новый URL.
